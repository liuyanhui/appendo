## 概述

Appendo 是一个 Android 速记应用，支持两种方式收集内容：
1. 接收由其他应用通过分享功能发送的链接或文字
2. 用户在应用内手动输入文字内容

所有内容追加保存到一个 Markdown 文件中，便于整理和导出。

## 功能需求

### 1. 接收与写入

1. **接收分享** — 作为分享目标（`ACTION_SEND`），接收 `text/plain` 类型的文本或链接
2. **手动输入** — 应用内提供对话框供用户直接输入文字内容，自动弹出键盘，支持多行输入（3-6行）
3. **追加写入** — 保持原有格式（换行、括号、空格、缩进等），不做任何文本处理，使用 UTF-8 编码无 BOM；写入操作加全局同步锁防止跨实例并发冲突
4. **条目格式** — 每条记录使用以下固定模板：

```
---

## YYYY-MM-DD HH:mm:ss

{原始内容}

---
```

5. **内容安全校验** — 分享接收时验证内容长度（最大 10,000 字符），防止恶意超长内容

### 2. 文件管理

6. **默认文件存储** — 首次启动自动在应用私有目录创建 `Appendo.md` 文件，开箱即用，无需用户选择
7. **自定义目录** — 通过菜单"自定义目录"选项，使用 SAF `CreateDocument` 让用户选择外部存储位置，保存并持久化 URI 权限
8. **双存储模式** — 支持默认模式（`FileBasedMarkdownFile`）和 SAF 模式（`SafMarkdownFile`），通过工厂类自动切换
9. **文件头** — 首次创建时写入 `# Appendo`；一键清理时保留文件头，仅清除条目内容
10. **文件丢失恢复** — SAF 模式下文件不存在或 URI 权限失效时，自动回退到默认模式
11. **追加降级** — SAF `MODE_APPEND` 失败时，降级为先读取全部内容再整体覆写
12. **归档** — 归档当前文件：自动在同一目录创建 `Appendo_yyyyMMdd_HHmmss.md` 文件并复制当前内容，当前文件保留不变，条目计数不变
13. **清空备份** — 清空操作前自动备份当前内容到归档文件，防止误删

### 3. 主界面

14. **状态展示** — 标题栏显示应用名和已收集条目数
15. **内容预览** — 实时显示所有已收集的条目列表，按时间倒序排列（最新的在前），每条显示时间戳和内容（最多3行，超出省略）
16. **操作按钮** — 2x2 网格布局：手动输入（蓝色实心）、复制全部（蓝色描边）、分享全部（蓝色描边）、清空（红色描边，长按触发）
17. **菜单功能** — 下拉菜单提供：归档、归档管理、打开文件、自定义目录、关于
    > 注（2026-09-17）：v1.1/v1.2 已加入"提醒自检"等提醒相关入口（需求见第 13 章回填）；v1.3 将新增"主题"项（需求 48）
18. **关于对话框** — 显示应用名称、版本号、功能简介、作者信息
19. **实时刷新** — 每 2 秒轮询检测文件修改时间变化，自动刷新条目列表
20. **空状态** — 无条目时显示引导提示文字

### 4. 条目交互

21. **长按复制** — 长按单条内容，复制该条内容到剪贴板，带短震动反馈（100ms）
22. **右滑删除** — 向右滑动超过阈值，显示红色背景和"删除"文字，松手后弹出确认对话框，确认后按时间戳删除该条目
23. **滑动指示** — 滑动过程中显示操作指示文字和背景色
24. **点击编辑** — 点击条目弹出编辑对话框，展示完整内容，修改后手动保存；时间戳保持不变；空内容不允许保存；归档详情页不触发编辑（只读）

### 5. 归档管理

24. **归档列表** — 菜单中"归档管理"入口，显示所有 `Appendo_*.md` 归档文件，按时间倒序排列，显示归档名、格式化时间和条目数
25. **点击查看** — 点击归档文件，进入归档详情页，查看该归档的所有条目（只读模式，支持长按复制）
26. **长按复制** — 长按归档文件，复制该归档的全部内容到剪贴板
27. **右滑删除** — 向右滑动归档文件，显示红色背景和"删除"文字，松手后弹出确认对话框
28. **左滑追加** — 向左滑动归档文件，显示绿色背景和"追加"文字，松手后弹出确认对话框，确认后将归档中不重复的条目追加到当前文档（按时间戳+内容去重）

### 6. 交互一致性

29. **震动反馈** — 所有长按和滑动操作都带震动反馈，提供触觉确认
30. **确认对话框** — 删除和追加操作都需要用户确认，防止误操作；标题颜色区分操作类型（删除=红色，追加=绿色）
31. **视觉反馈** — 滑动过程中显示操作指示文字和背景色
32. **自适应图标** — 支持圆形和方形自适应图标（API 26+），蓝色背景 + 白色记事本与羽毛笔矢量前景

### 7. 容错

33. **分享写入反馈** — 分享写入完成后通过 Toast 提示用户
34. **SAF 降级** — SAF URI 失效时自动回退到默认文件存储
35. **日志记录** — DEBUG 模式下记录关键操作日志，便于排查问题

### 8. 数据完整性与健壮性（v1.1）

36. **条目唯一标识** — 每条新写入的条目须有全局唯一的时间戳标识；同一秒内多次写入不得产生相同标识，采用毫秒级精度实现。（决策背景：当前为手动触发，秒级碰撞概率极低；但毫秒级修复成本极小，且为未来批量/自动化写入兜底。）
37. **时间戳格式兼容** — 解析器须同时识别秒级（历史归档）与毫秒级（新写入）两种时间戳格式，确保归档恢复等流程不丢数据。无需主动迁移旧文件，但读取必须兼容。
38. **内容隔离**（修订原需求 3"不做任何文本处理"）— 为防止用户内容中恰好匹配时间戳标记格式的行被误判为条目边界，允许在写入时对【仅此类行】做最小且可逆的处理。约束：(a) 仅作用于"会与条目标记混淆"的行，其余内容字节级原样写入；(b) 可逆——读取/展示时还原为用户原文，用户可见内容与输入完全一致；(c) 不改变用户内容的语义。
39. **写入原子性** — 追加、删除、更新、清空等写操作须保证原子性：操作过程中崩溃/中断/被杀不得导致文件损坏或数据丢失（如临时文件 + 原子重命名）。**模式差异**：默认文件模式为真原子（temp + fsync + rename）；SAF 模式因 SAF 无原子重命名 API，采用"软恢复"语义——崩溃后回滚到上次已知良好状态（.bak），**最近一次未确认写入可能丢失，但不损坏文件**。
40. **并发安全** — 跨 Activity、跨实例的并发写不得相互破坏（延续现有全局锁机制）。

### 9. 重复内容处理（v1.1）

41. **追加不去重（保真优先）** — 手动输入与分享接收路径始终创建新条目，不因内容与已有条目相同而静默丢弃或合并。理由：捕获类应用的核心承诺是"用户提交的内容不丢失"；重复内容由用户自行删除。
42. **重复内容提示（非阻塞）** — 追加后若内容与已有条目相同（按内容比较，忽略时间戳），以非阻塞 Toast 告知"此内容已存在"，但不阻止写入。
43. **归档恢复去重（透明）** — 归档恢复维持按 `timestamp|content` 去重，但须在结果提示中明示"跳过 N 条已存在条目"，不静默丢弃。

### 10. 验收场景（v1.1 必测）

44. **归档恢复追加** — 从归档恢复条目到当前文档：旧秒级与新毫秒级条目混合解析正确；去重正确；含注入行的归档条目恢复后不被错误切分。
45. **复制再追加（往返一致）** — 从当前文档读取的内容再次追加：隔离标记被正确重新添加；write→read→write 往返后内容不变；含注入行的内容复制再追加仍解析为单条。
46. **写中断恢复** — 模拟写入过程中断，文件不损坏、可正常解析。

> 需求 47（菜单"查找重复内容"工具）建议挪至后续产品完善阶段，非 v1.1 必做。

### 11. 主题外观（v1.3）

48. **主题三态设置** — 菜单新增"主题"设置项，提供三态选择：**跟随系统**（默认）/ **浅色** / **深色**。默认跟随系统深浅色，用户未手动选择前不持久化覆盖默认行为。存量用户升级后默认即生效"跟随系统"——深色系统下界面将由恒浅色变为深色，属可感知的显式变更，须在 CHANGELOG 与 README 注明
49. **偏好持久化** — 用户手动选择的主题模式持久化保存，应用重启后保持上次选择
50. **即时生效与实时跟随** — 切换主题模式后界面立即切换，无需重启应用，且切换过程中导航栈与主页列表滚动位置保持（不重置）；跟随系统模式下应用在前台时，系统深浅色切换须实时跟随
51. **深色适配范围** — 应用自身渲染的所有页面与组件完整适配两种主题：主页、归档列表、归档详情、条目卡片（含滑动删除/追加的彩色背景）、全部对话框（截至 v1.3 包括：手动输入、条目编辑、各类确认、关于、提醒时间选择、提醒自检、首启存储引导、主题选择自身；后续新增对话框默认适用）、下拉菜单、分享接收 Activity 的窗口背景；Toast 在两种主题下均可读（现有样式即满足，不随主题变色）；状态栏图标外观随主题切换（浅色主题用深色图标、深色主题用浅色图标）
52. **强调色可读性** — 现有强调色（Primary 蓝 / Danger 红 / Success 绿）在深浅两种背景下均须满足可读对比度（量化门槛在设计阶段明确），必要时为深色主题提供提亮变体；浅色主题现有配色若经量化检验不达标，是否同步调整由设计阶段决策

**已知约束与排除项**（属已知边界，验收时不作为缺陷上报）：

- 系统/三方 UI（SAF 文件选择器、系统权限对话框、输入法等）按系统主题渲染，不受应用内手动主题选择控制
- API 26/27 设备无系统级深色开关，"跟随系统"自然恒为浅色
- 通知配色由系统按自身深浅渲染，本需求不涉及通知适配
- 自适应图标 monochrome 层（Android 13 Themed Icons）本期不做
- AMOLED 纯黑主题、Material You 动态取色本期不做

### 12. 主题验收场景（v1.3 必测）

53. **三态切换** — 手动切换 浅色↔深色↔跟随系统，界面即时切换且重启后选择保持；切换过程中导航栈与主页列表滚动位置保持（不重置）
54. **跟随系统** — (a) 应用在前台时系统深浅切换，界面实时跟随；(b) 应用在后台期间系统切换，回前台后（含从提醒通知深链进入）主题正确；(c) 切回手动模式后不再受系统影响
55. **深色走查** — 深色主题下逐页走查：三个页面 + 全部对话框 + 下拉菜单 + 空状态页（需求 20），无不可读文字、无浅色残块；显式检查滑动删除/追加中间态（红/绿背景上的白字）与状态栏图标深浅
56. **冷启动一致性** — 冷启动窗口背景与所选主题一致（跟随系统模式按系统当前主题；手动模式按手动选择），无可感知闪烁；深色系统下发起分享（ShareReceiverActivity 路径）不出现白闪

### 13. 本地提醒（v1.1.0 / v1.2.0 已发布功能，2026-09-17 回填）

> 本章为存量文档债务回填：v1.1.0/v1.2.0 功能先于需求文档发布，现按已发布并真机验收的实现补记（2026-09-17 主题需求评审发现）。技术机制详见 `docs/architecture.md` §5。

57. **本地提醒设置** — 条目详情对话框可为单条记录设置提醒时间（预设时间档 + 自定义日期时间，含"每天/每周"重复选项）；手动输入对话框可直接为新增内容设置提醒。提醒为本地实现：不经日历、应用自身不联网、由本应用直接发通知
58. **提醒触发与通知** — 到点发送高优先级通知；点按通知深链回应用并滚动到对应记录；提供"贪睡 10 分钟 / 贪睡 1 小时 / 完成"通知操作；触发时条目已被删除则自动取消该提醒（自愈）
59. **重复提醒语义** — 每天/每周重复提醒触发后自动排下一次；通知操作"完成"保留系列继续排期，详情页"取消提醒"终结系列
60. **贪睡漂移（有意取舍）** — 重复提醒贪睡后以贪睡时刻为新锚点排后续（系列永久后移），属有意设计，已在 README 向用户声明
61. **通知权限守卫** — Android 13+ 无通知权限时先请求权限，用户拒绝则不创建提醒（不允许设置必然无声的提醒）
62. **开机与更新恢复** — 设备重启（首次解锁后）自动重注册未触发的提醒并补发错过的（重复提醒只补最新一次，不刷屏）；应用更新/被强停后，下次启动自动重注册并补发
63. **与条目联动** — 删除条目联动取消其提醒；清空文档联动取消全部提醒；提醒对应的条目在外部被移除时自动清理（孤儿对账）
64. **提醒徽标** — 列表中设有未触发提醒的条目显示提醒徽标；触发、取消、完成即刻更新（不依赖文件轮询）
65. **提醒自检** — 菜单"提醒自检"入口：通知权限检查、电池优化白名单检查（可一键跳转）、自启动设置跳转、发送测试提醒（1 分钟后触发）
66. **可靠性边界（声明式契约）** — 可靠性契约为"完成一次性设置后可当场验证、对大多数用户可靠"，非 100% 保证（接收器被杀无法自动预测）；重启后需解锁一次才补发。以上边界已在 README 向用户声明
67. **添加到日历（次要路径）** — 条目详情与手动输入对话框提供"添加到日历"按钮：预填标题与时间跳转系统日历（fire-and-forget，不回读，不作为提醒可靠性路径）

### 14. 出口格式化（v1.3）

> 背景（2026-09-18 真机实测）：现"复制全部/分享全部"导出**文件原文**，含 `## 时间戳`、条目间连续多行 `---`、文件头 `# Appendo` 等结构标记。部分接收端（有道云笔记、realme 便签）对分享文本做智能结构解析，只显示第一条；微信等纯文本接收虽完整但标记是显示噪音。复制/分享是内容离开本应用的主路径（见 CLAUDE.md 用户使用习惯），导出须干净。

68. **复制/分享导出格式** — "复制全部"与"分享全部"的导出内容从文件原文改为**格式化纯文本**：每条为"`YYYY-MM-DD HH:mm:ss`"（秒级，无毫秒）一行 + 空行 + 条目内容；条目之间以空行分隔。不含 `##`、`# Appendo`、`---` 等 Markdown 结构标记。（2026-09-18 实现时纳入同类全文复制出口：归档列表长按复制归档全文，同格式）
69. **条目顺序** — 导出顺序与文件存储顺序一致（最旧在前），与现状相同
70. **内容语义** — 导出沿用解析显示层语义：时间戳为显示格式；内容去除首尾空白行（与界面显示一致）；ZWSP 隔离标记不出现在导出中（经 parse 产物构建，满足内容隔离不变量 2）
71. **单条复制不变** — 长按复制单条仍为仅条目内容、无时间戳行
72. **其他出口不变** — 添加到日历预填、通知标题、文件存储格式（Markdown 协议/解析器/数据完整性机制）均不受影响。格式化导出仅供人读与外部粘贴，**不承诺可再导入还原**（再导入保真仍以文件本身为准）
73. **验收（v1.3 必测）** — (a) 分享全部到有道云笔记与系统便签：全部条目完整可见；(b) 复制全部粘贴微信/编辑器：完整且无结构标记；(c) 单条复制行为不变；(d) 空文件时"暂无内容可复制/分享"提示保持；(e) 导出文本无零宽字符（字符级检查）

## 技术要求

- **技术栈**：Kotlin + Jetpack Compose (Material 3)

- **文件存储**：双模式 — 默认（应用私有目录）+ SAF (Storage Access Framework)
- **最低 SDK**：API 26 (Android 8.0)
- **目标 SDK**：API 34
- **构建**：JDK 17，Gradle 9.x，AGP 9.x，Kotlin 2.2.x
- **无第三方业务依赖**：仅使用 AndroidX 官方库
