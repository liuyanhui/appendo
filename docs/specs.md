## 概述

Appendo 是一个 Android 速记应用，支持两种方式收集内容：
1. 接收由其他应用通过分享功能发送的链接或文字
2. 用户在应用内手动输入文字内容

所有内容追加保存到一个 Markdown 文件中，便于整理和导出。

## 功能需求

### 1. 接收与写入

1. **接收分享** — 作为分享目标（`ACTION_SEND`），接收 `text/plain` 类型的文本或链接
2. **手动输入** — 应用内提供对话框供用户直接输入文字内容，自动弹出键盘，支持多行输入（3-6行）
3. **追加写入** — 保持原有格式（换行、括号、空格、缩进等），不做任何文本处理，使用 UTF-8 编码无 BOM；写入操作加全局同步锁防止跨实例并发冲突
4. **条目格式** — 每条记录使用以下固定模板：

```
---

## YYYY-MM-DD HH:mm:ss

{原始内容}

---
```

5. **内容安全校验** — 分享接收时验证内容长度（最大 10,000 字符），防止恶意超长内容

### 2. 文件管理

6. **默认文件存储** — 首次启动自动在应用私有目录创建 `Appendo.md` 文件，开箱即用，无需用户选择
7. **自定义目录** — 通过菜单"自定义目录"选项，使用 SAF `CreateDocument` 让用户选择外部存储位置，保存并持久化 URI 权限
8. **双存储模式** — 支持默认模式（`FileBasedMarkdownFile`）和 SAF 模式（`SafMarkdownFile`），通过工厂类自动切换
9. **文件头** — 首次创建时写入 `# Appendo`；一键清理时保留文件头，仅清除条目内容
10. **文件丢失恢复** — SAF 模式下文件不存在或 URI 权限失效时，自动回退到默认模式
11. **追加降级** — SAF `MODE_APPEND` 失败时，降级为先读取全部内容再整体覆写
12. **归档** — 归档当前文件：自动在同一目录创建 `Appendo_yyyyMMdd_HHmmss.md` 文件并复制当前内容，当前文件保留不变，条目计数不变
    > 注（2026-11-04）：入口自菜单迁移至 2x2 网格「归档」二选一之「只归档，保留列表」选项，快照语义不变（第 16 章 93）
13. **清空备份** — 清空操作前自动备份当前内容到归档文件，防止误删
    > 注（2026-11-04）：清空入口并入 2x2 网格「归档」二选一之「归档并清空」（默认焦点），先备份后清空与归档失败中止（TD-017）承诺不变；不设无备份清空选项（第 16 章 93）

### 3. 主界面

14. **状态展示** — 标题栏显示应用名和已收集条目数
15. **内容预览** — 实时显示所有已收集的条目列表，按时间倒序排列（最新的在前），每条显示时间戳和内容（最多3行，超出省略）
16. **操作按钮** — 2x2 网格布局：手动输入（蓝色实心）、复制全部（蓝色描边）、分享全部（蓝色描边）、清空（红色描边，长按触发）

17. **菜单功能** — 下拉菜单提供：归档、归档管理、打开文件、自定义目录、关于
    > 注（2026-09-17）：v1.1/v1.2 已加入"提醒自检"等提醒相关入口（需求见第 13 章回填）；v1.3 将新增"主题"项（需求 48）

### 8. 数据完整性与健壮性（v1.1）

36. **条目唯一标识** — 每条新写入的条目须有全局唯一的时间戳标识；同一秒内多次写入不得产生相同标识，采用毫秒级精度实现。（决策背景：当前为手动触发，秒级碰撞概率极低；但毫秒级修复成本极小，且为未来批量/自动化写入兜底。）
37. **时间戳格式兼容** — 解析器须同时识别秒级（历史归档）与毫秒级（新写入）两种时间戳格式，确保归档恢复等流程不丢数据。无需主动迁移旧文件，但读取必须兼容。
38. **内容隔离**（修订原需求 3"不做任何文本处理"）— 为防止用户内容中恰好匹配时间戳标记格式的行被误判为条目边界，允许在写入时对【仅此类行】做最小且可逆的处理。约束：(a) 仅作用于"会与条目标记混淆"的行，其余内容字节级原样写入；(b) 可逆——读取/展示时还原为用户原文，用户可见内容与输入完全一致；(c) 不改变用户内容的语义。
39. **写入原子性** — 追加、删除、更新、清空等写操作须保证原子性：操作过程中崩溃/中断/被杀不得导致文件损坏或数据丢失（如临时文件 + 原子重命名）。**模式差异**：默认文件模式为真原子（temp + fsync + rename）；SAF 模式因 SAF 无原子重命名 API，采用"软恢复"语义——崩溃后回滚到上次已知良好状态（.bak），**最近一次未确认写入可能丢失，但不损坏文件**。
40. **并发安全** — 跨 Activity、跨实例的并发写不得相互破坏（延续现有全局锁机制）。

### 9. 重复内容处理（v1.1）

41. **追加不去重（保真优先）** — 手动输入与分享接收路径始终创建新条目，不因内容与已有条目相同而静默丢弃或合并。理由：捕获类应用的核心承诺是"用户提交的内容不丢失"；重复内容由用户自行删除。
42. **重复内容提示（非阻塞）** — 追加后若内容与已有条目相同（按内容比较，忽略时间戳），以非阻塞 Toast 告知"此内容已存在"，但不阻止写入。
    > 注（2026-10-06）：Toast 文案字面以第 15 章术语表及需求 74 定稿为准（现文案"已有相同内容 N 条"作为成功反馈的后缀附注保留，语义不变）
43. **归档恢复去重（透明）** — 归档恢复维持按 `timestamp|content` 去重，但须在结果提示中明示"跳过 N 条已存在条目"，不静默丢弃。

### 14. 出口格式化（v1.3）

> 背景（2026-09-18 真机实测）：现"复制全部/分享全部"导出**文件原文**，含 `## 时间戳`、条目间连续多行 `---`、文件头 `# Appendo` 等结构标记。部分接收端（有道云笔记、realme 便签）对分享文本做智能结构解析，只显示第一条；微信等纯文本接收虽完整但标记是显示噪音。复制/分享是内容离开本应用的主路径（见 CLAUDE.md 用户使用习惯），导出须干净。

68. **复制/分享导出格式** — "复制全部"与"分享全部"的导出内容从文件原文改为**格式化纯文本**：每条为"`YYYY-MM-DD HH:mm:ss`"（秒级，无毫秒）一行 + 空行 + 条目内容；条目之间以空行分隔。不含 `##`、`# Appendo`、`---` 等 Markdown 结构标记。（2026-09-18 实现时纳入同类全文复制出口：归档列表长按复制归档全文，同格式）
69. **条目顺序** — 导出顺序与文件存储顺序一致（最旧在前），与现状相同
70. **内容语义** — 导出沿用解析显示层语义：时间戳为显示格式；内容去除首尾空白行（与界面显示一致）；ZWSP 隔离标记不出现在导出中（经 parse 产物构建，满足内容隔离不变量 2）
71. **单条复制不变** — 长按复制单条仍为仅条目内容、无时间戳行
72. **其他出口不变** — 添加到日历预填、通知标题、文件存储格式（Markdown 协议/解析器/数据完整性机制）均不受影响。格式化导出仅供人读与外部粘贴，**不承诺可再导入还原**（再导入保真仍以文件本身为准）
73. **验收（v1.3 必测）** — (a) 分享全部到有道云笔记与系统便签：全部条目完整可见；(b) 复制全部粘贴微信/编辑器：完整且无结构标记；(c) 单条复制行为不变；(d) 空文件时"暂无内容可复制/分享"提示保持；(e) 导出文本无零宽字符（字符级检查）

### 16. 主题分拣——「移入主题」（2026-10-30）

> 背景（2026-10-30 需求分析，依据真实使用样例 24 条，2026-06-30~10-27）：单一时间线混杂多主题（英语学习、AI 行业观察、链接等），无法按主题取用；想把某主题条目拷去微信只能逐条长按复制。本章新增「移入主题」：主列表多选条目，移动式合并到**手机本地主题文档**。基础裁定（2026-10-30 用户确认）：(1) 目标为本地主题文档；(2) 移动式——原条目从当前文件移除；(3) 一批只移入一个文档（多目标＝多批操作）；(4) 功能名「移入主题」；(5) 主题文档自由命名；(6) 独立本地功能，与「碎片直投生产线」（raw-pile/grill-me/appendo-inbox-sync）无关——将来投递功能若需覆盖主题文档，届时另行裁定。移动式不得动摇需求 41「内容不丢失」承诺，故 84（原子性）与 86（恢复路径）为硬约束。主题文档的存储位置与双模式（默认/SAF）适配方式在设计阶段定。

96. **移出与主题间转移（L1）** — 主题详情多选条目后：「**移出**」＝搬回主列表（移动式，源主题删除原条目；不复用恢复交互）；「**移入其他主题**」＝转入其他主题（一批一文档不变）；「**删除**」见 97(d)。**批量动作按钮字面钉死**：「移出到主列表」「移入其他主题」「删除」——不得用裸「移入主题」（主题语境下读作移入当前主题，歧义）。事务硬约束**镜像 84**：先成功写入目标（主列表或目标主题）后才从源主题删除，任何情况下不出现「两边都没有」；**源文档＝目标文档拒绝**（事务层文件同一性护栏＋目标选择列表排除当前主题——防同文档自移致条目被删光却报成功的数据丢失路径）；条目按时间戳升序追加到目标末尾（83 镜像，主列表目标同口径）；SAF 主文件作目标时沿用软中间态＋重试幂等收敛（84(g) 口径）；按 `timestamp|content` 寻址（84(e) 镜像）；去重透明（87 镜像：目标已存在相同条目跳过写入、源仍删除；N=0 全部已存在仍属成功无歧义）；计数口径 N/M 可核对（88 镜像）；**确认去向句分场景**：移出「将 N 条移出到主列表。」、转移「将 N 条移入「X」，并从「当前主题」移除。」（不套用主列表源模板——源是主题时写「从主列表移除」为事实错误）；失败「移出失败/移入失败」＋保持勾选可一键重试（84(b) 镜像；SAF 授权失效变体文案设计定稿）。技术前提（写入设计）：移入组合事务**通用化**为「源∈{主文件, 主题}、目标∈{主文件, 主题}」；目标存在性判定**按模式分离**——SAF 目标「无法判定」（授权失效）须与「不存在」分离、归入目标读取失败（干净失败，防授权失效被误当不存在而覆写），FileBased 目标维持 exists() 分支（不存在→文件头起步，免误判懒创建）。
97. **主题内条目操作（L2＋L3，B 档对齐）** — 主题详情页自只读升级为工作区，条目级操作与主列表同权：

    (c) **新增** — 主题详情提供新增入口（对话框与主列表手动输入一致：多行输入、键盘自动弹出、确认「保存」、重复内容非阻塞提示——41/42/74/76/79 口径镜像；次级动作先落盘——75 复用）；新条目毫秒时间戳、**主题文档内唯一**（36 镜像）；不承诺跨文档 ts 唯一（恢复副本本就同 ts 两处并存，提醒归属按 95(b)(c) 口径）；**目的地标识（硬要求）**：成功反馈须带主题名（如「已追加到「主题名」」，沿「已归档到 name」「已追加到默认文件」先例——速记属肌肉记忆操作，无标识则条目静默落主题、主列表找不到；字面设计定稿）；
    (d) **多选** — 主题详情支持多选（82 口径镜像：选中集按条目唯一标识、随列表重载保持、打勾交互、全文预览途径）；**长按单条＝复制（需求 21），多选入口不得占用长按复制**（主列表手势分配约束显式带过来）；批量动作＝移出/移入其他主题/删除（96）；**批量删除**：确认框明示所选 N 条（error 红，30/78 口径），成功/失败反馈字面设计定稿，提醒联动按 95(e)；

#### 16.C 修订四——自建提醒退役·系统日历替代（2026-11-16 用户裁定；**定稿——同日用户确认，方案 A**）

#### 16.D 修订五——工作区功能补全＋批量清理（2026-11-17 起草/同日评审修订；**定稿——2026-11-18 用户确认**）

**范围**：落地 16.C 保留的 97（去提醒项）与 98 条文＋新增强需求；成批＝「己批次」。

- **102 主题内条目操作（97 落地）**：
  (a) 编辑——点击条目→编辑对话框，`updateEntry(ts, newContent)` 按 ts 命中首条；保存后主题重载；时间戳不变；
  (b) 删除——右滑→确认框（error 红＋振动）→`deleteEntries(同 key 全删)`→重载；全删归一化纯文件头；**随此修复 v1.5.0 的右滑指示误导**（指示有删除无动作）；
  (c) 批量删除——多选 bar 第三钮「删除」，确认框明示 N（沿 dlgBatchDeleteBody 句式族）；
  (d) 新增——顶栏「＋」→输入对话框（复用主列表先例：空校验/重复提示/草稿保全，**含「添加到日历」主按钮——16.C 承接同权**），`appendReturningTimestamp`；成功 toast 含主题名（目的地标识）；顶栏计数 N+1；

  (f) **功能对齐原则（用户 2026-11-17 裁定）**——主题条目与主界面条目同权：**条目级操作全集对齐**（(a)~(g)＋16.B 96/97(d) 多选移出/转移），**一律复用主界面实现**（见 106），不得复制粘贴平行实现；主界面专属能力**不迁移**：分享接收（写主文件的收集箱心智）/打开文件/自定义目录/归档管理入口/外观/2 秒轮询（97(f) 明示排除）；多选批量删除为**有意不对称**（主列表走「移入主题后清理」心智）；
  (h) **展示排序**：工作区条目列表与主列表同口径（时间倒序、最新在顶）——消除同权界面双顺序的肌肉记忆冲突；
  (g) 归档——主题内复用「归档二选一」（入口＝溢出菜单）：只归档＝主题条目备份；归档并清空＝备份＋清空（文件归一化纯文件头）。**主题归档件语义（2026-11-18 三方收敛裁定）**：命名 `Appendo_<主题名>_<时间戳>.md`＋**同步扩展归档解析器**（防严格解析静默剔除）＋归档卡显示来源主题名＋**同秒递增后缀**（连续清理场景防覆盖备份——数据安全）；恢复目的地＝主文件（沿 86 语义，README 注明）；二选一框正文一层内明示作用域「将备份并清空主题『X』的 N 条」（不叠第二层确认）。
