## 概述

Appendo 是一个 Android 速记应用，支持两种方式收集内容：
1. 接收由其他应用通过分享功能发送的链接或文字
2. 用户在应用内手动输入文字内容

所有内容追加保存到一个 Markdown 文件中，便于整理和导出。

## 功能需求

### 1. 接收与写入

1. **接收分享** — 作为分享目标（`ACTION_SEND`），接收 `text/plain` 类型的文本或链接
2. **手动输入** — 应用内提供对话框供用户直接输入文字内容，自动弹出键盘，支持多行输入（3-6行）
3. **追加写入** — 保持原有格式（换行、括号、空格、缩进等），不做任何文本处理，使用 UTF-8 编码无 BOM；写入操作加全局同步锁防止跨实例并发冲突
4. **条目格式** — 每条记录使用以下固定模板：

```
---

## YYYY-MM-DD HH:mm:ss

{原始内容}

---
```

5. **内容安全校验** — 分享接收时验证内容长度（最大 10,000 字符），防止恶意超长内容

### 2. 文件管理

6. **默认文件存储** — 首次启动自动在应用私有目录创建 `Appendo.md` 文件，开箱即用，无需用户选择
7. **自定义目录** — 通过菜单"自定义目录"选项，使用 SAF `CreateDocument` 让用户选择外部存储位置，保存并持久化 URI 权限
8. **双存储模式** — 支持默认模式（`FileBasedMarkdownFile`）和 SAF 模式（`SafMarkdownFile`），通过工厂类自动切换
9. **文件头** — 首次创建时写入 `# Appendo`；一键清理时保留文件头，仅清除条目内容
10. **文件丢失恢复** — SAF 模式下文件不存在或 URI 权限失效时，自动回退到默认模式
11. **追加降级** — SAF `MODE_APPEND` 失败时，降级为先读取全部内容再整体覆写
12. **归档** — 归档当前文件：自动在同一目录创建 `Appendo_yyyyMMdd_HHmmss.md` 文件并复制当前内容，当前文件保留不变，条目计数不变
13. **清空备份** — 清空操作前自动备份当前内容到归档文件，防止误删

### 3. 主界面

14. **状态展示** — 标题栏显示应用名和已收集条目数
15. **内容预览** — 实时显示所有已收集的条目列表，按时间倒序排列（最新的在前），每条显示时间戳和内容（最多3行，超出省略）
16. **操作按钮** — 2x2 网格布局：手动输入（蓝色实心）、复制全部（蓝色描边）、分享全部（蓝色描边）、清空（红色描边，长按触发）
17. **菜单功能** — 下拉菜单提供：归档、归档管理、打开文件、自定义目录、关于
18. **关于对话框** — 显示应用名称、版本号、功能简介、作者信息
19. **实时刷新** — 每 2 秒轮询检测文件修改时间变化，自动刷新条目列表
20. **空状态** — 无条目时显示引导提示文字

### 4. 条目交互

21. **长按复制** — 长按单条内容，复制该条内容到剪贴板，带短震动反馈（100ms）
22. **右滑删除** — 向右滑动超过阈值，显示红色背景和"删除"文字，松手后弹出确认对话框，确认后按时间戳删除该条目
23. **滑动指示** — 滑动过程中显示操作指示文字和背景色
24. **点击编辑** — 点击条目弹出编辑对话框，展示完整内容，修改后手动保存；时间戳保持不变；空内容不允许保存；归档详情页不触发编辑（只读）

### 5. 归档管理

24. **归档列表** — 菜单中"归档管理"入口，显示所有 `Appendo_*.md` 归档文件，按时间倒序排列，显示归档名、格式化时间和条目数
25. **点击查看** — 点击归档文件，进入归档详情页，查看该归档的所有条目（只读模式，支持长按复制）
26. **长按复制** — 长按归档文件，复制该归档的全部内容到剪贴板
27. **右滑删除** — 向右滑动归档文件，显示红色背景和"删除"文字，松手后弹出确认对话框
28. **左滑追加** — 向左滑动归档文件，显示绿色背景和"追加"文字，松手后弹出确认对话框，确认后将归档中不重复的条目追加到当前文档（按时间戳+内容去重）

### 6. 交互一致性

29. **震动反馈** — 所有长按和滑动操作都带震动反馈，提供触觉确认
30. **确认对话框** — 删除和追加操作都需要用户确认，防止误操作；标题颜色区分操作类型（删除=红色，追加=绿色）
31. **视觉反馈** — 滑动过程中显示操作指示文字和背景色
32. **自适应图标** — 支持圆形和方形自适应图标（API 26+），蓝色背景 + 白色记事本与羽毛笔矢量前景

### 7. 容错

33. **分享写入反馈** — 分享写入完成后通过 Toast 提示用户
34. **SAF 降级** — SAF URI 失效时自动回退到默认文件存储
35. **日志记录** — DEBUG 模式下记录关键操作日志，便于排查问题

### 8. 数据完整性与健壮性（v1.1）

36. **条目唯一标识** — 每条新写入的条目须有全局唯一的时间戳标识；同一秒内多次写入不得产生相同标识，采用毫秒级精度实现。（决策背景：当前为手动触发，秒级碰撞概率极低；但毫秒级修复成本极小，且为未来批量/自动化写入兜底。）
37. **时间戳格式兼容** — 解析器须同时识别秒级（历史归档）与毫秒级（新写入）两种时间戳格式，确保归档恢复等流程不丢数据。无需主动迁移旧文件，但读取必须兼容。
38. **内容隔离**（修订原需求 3"不做任何文本处理"）— 为防止用户内容中恰好匹配时间戳标记格式的行被误判为条目边界，允许在写入时对【仅此类行】做最小且可逆的处理。约束：(a) 仅作用于"会与条目标记混淆"的行，其余内容字节级原样写入；(b) 可逆——读取/展示时还原为用户原文，用户可见内容与输入完全一致；(c) 不改变用户内容的语义。
39. **写入原子性** — 追加、删除、更新、清空等写操作须保证原子性：操作过程中崩溃/中断/被杀不得导致文件损坏或数据丢失（如临时文件 + 原子重命名）。**模式差异**：默认文件模式为真原子（temp + fsync + rename）；SAF 模式因 SAF 无原子重命名 API，采用"软恢复"语义——崩溃后回滚到上次已知良好状态（.bak），**最近一次未确认写入可能丢失，但不损坏文件**。
40. **并发安全** — 跨 Activity、跨实例的并发写不得相互破坏（延续现有全局锁机制）。

### 9. 重复内容处理（v1.1）

41. **追加不去重（保真优先）** — 手动输入与分享接收路径始终创建新条目，不因内容与已有条目相同而静默丢弃或合并。理由：捕获类应用的核心承诺是"用户提交的内容不丢失"；重复内容由用户自行删除。
42. **重复内容提示（非阻塞）** — 追加后若内容与已有条目相同（按内容比较，忽略时间戳），以非阻塞 Toast 告知"此内容已存在"，但不阻止写入。
43. **归档恢复去重（透明）** — 归档恢复维持按 `timestamp|content` 去重，但须在结果提示中明示"跳过 N 条已存在条目"，不静默丢弃。

### 10. 验收场景（v1.1 必测）

44. **归档恢复追加** — 从归档恢复条目到当前文档：旧秒级与新毫秒级条目混合解析正确；去重正确；含注入行的归档条目恢复后不被错误切分。
45. **复制再追加（往返一致）** — 从当前文档读取的内容再次追加：隔离标记被正确重新添加；write→read→write 往返后内容不变；含注入行的内容复制再追加仍解析为单条。
46. **写中断恢复** — 模拟写入过程中断，文件不损坏、可正常解析。

> 需求 47（菜单"查找重复内容"工具）建议挪至后续产品完善阶段，非 v1.1 必做。

## 技术要求

- **技术栈**：Kotlin + Jetpack Compose (Material 3)
- **导航**：Navigation Compose
- **文件存储**：双模式 — 默认（应用私有目录）+ SAF (Storage Access Framework)
- **最低 SDK**：API 26 (Android 8.0)
- **目标 SDK**：API 34
- **构建**：JDK 17，Gradle 9.x，AGP 9.x，Kotlin 2.2.x
- **无第三方业务依赖**：仅使用 AndroidX 官方库
