## 0. 使用说明

### 0.1 用例分层

- **P0（发布门禁）**：核心路径与数据安全——发布前必须全过；
- **P1（质量门）**：重要分支与边界——每批次开发完成时过，发布前抽查；
- **P2（回归池）**：低频路径与视觉项——按需。

### 0.2 验证方式标注

- **JVM**：已有单元测试覆盖（标注测试类），`./gradlew :Appendo:testDebugUnitTest` 全绿即视为过；
- **真机**：人工走查（真机 RMX3560；toast 观察以人眼为准——TD-024 约束）；
- **adb 可代驱**：可用 adb input/dump 自动化驱动（注意：`input swipe` 在部分设备状态下失灵，用 `motionevent` 逐点拖动替代——2026-11-17 在案）。

### 0.3 验收标准（发布门槛）

1. 全量 JVM 单测绿（当前 210 项，0 失败 0 错误）；
2. 本文档 **P0 用例全过**（JVM 项随测试套件、真机项人工签字）；
3. P1 抽查 ≥3 项（含 1 项数据安全类）；
4. CHANGELOG 对应版本段已定稿。

## 9. 已知边界与不测项（如实声明）

- 外部编辑器直编 `Appendo.md` 不受支持（README 已知限制）；
- 写入日历的事件由日历应用管理，应用不读不删（16.C 设计）；
- `input swipe` 在部分设备状态下注入失灵——自动化一律用 motionevent 逐点拖动；
- 真机 FUSE 拒绝 run-as 访问外部 Android/data——文件级注入仅限内部 `files/topics` 候选目录。
